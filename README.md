# 个人工作生活台

只给自己用的本地工作台：九个模块共享同一份数据，不登录、不联网、不上云。关掉浏览器、重启电脑，数据都还在。

---

## 一、这个项目解决什么问题

一个人的事情通常散落在七八个工具里：待办清单记任务、Excel 记工时、备忘录记选题、日历记训练、记事本记客户跟进。工具之间不通，于是每天要花时间「搬运」和「回忆」——今天到底该做什么、那个客户上次谈到哪一步、这几条视频的数据怎么样。

这个项目把这些收进**一个只跑在本机的页面**：

| 痛点 | 这里的做法 |
|---|---|
| 每天不知道该做什么 | 任何模块里的具体事项都能「加入今天」，汇到同一张今日计划里，按上午/下午/晚上排 |
| 勾完待办，源头还是旧的 | 勾掉会**回写源实体**：任务变完成、Bug 变已解、跟进变已办 |
| 记录在别处，看完还得手抄 | 首页把六个模块的关键数字摆在一屏，点卡片直接跳过去 |
| 每个工具都要登录、要同步、怕停服 | 无账号、无网络请求，数据是本机 `data/` 下的一个 JSON 文件，随时整包拷走 |
| 记了几个月，翻不回去 | 健身、饮食用整月日历；自媒体有按日汇总的趋势曲线；咨询能按月汇总应收与已收 |

设计上有一条硬规则：**引用，不复制**。今日计划里的一条只是对源实体的引用，删掉源任务时计划条目不会跟着消失，而是标注「来源已删除」，避免误删连带丢记录。

## 二、主要功能

### 九个页面

| 页面 | 主要能力 |
|---|---|
| **首页总览** | 问候语与今日完成度进度环；今日计划三段直显；快速备忘；六张摘要卡（自媒体待发布 / 开发在跑项目与未解 Bug / 咨询下次会谈与待跟进 / 健身今天练什么与本周完成 / 饮食今天吃什么与喝水 / 娱乐本周时长与在玩），点卡片跳转对应模块 |
| **今日计划** | 上午/下午/晚上三段；新增、点标题就地重命名、勾选完成、点圆点循环切换优先级（普通/重要/紧急）；有预估时长时在行内显示；拖拽排序与跨段拖动；「移到」可选今天/明天/自定义日期；删除二次确认；昨天未完成自动提示顺延，可逐条或全部移到今天 |
| **自媒体** | 四个视图：**看板**（选题 → 写稿 → 待发布 → 已发布，可拖动换列）、**日历**（按发布日归集）、**列表**（表格直显标题/平台/阶段/计划发布/播放，可就地改阶段或删除）、**数据**（趋势图与对比图）。内容可记平台、发布时间、正文，回填播放/点赞/涨粉 |
| **开发工作** | 左侧项目列表（进行中/暂停/完成）；右侧四页签：**任务**（点状态按钮在待做 → 进行中 → 完成之间循环）、**Bug**（致命/严重/一般/轻微，未解/已解）、**工时**（计时器开始/暂停/继续/结束并记录，也可手填分钟）、**日志**（按日写开发日志）。项目头部显示累计工时与任务完成度 |
| **咨询工作** | 左侧客户列表；右侧四页签：**客户**（联系人、状态、备注）、**项目**（接洽/进行中/收尾/已结项，合同额与已收款展示）、**会谈**（日期、时长、主题、结论、下次跟进日）、**跟进**（截止日、逾期标红并排最前）。一键从会谈「生成跟进」；底部按月统计应收与已收 |
| **健身计划** | 整月日历：格子显示当天部位、动作数、组数，完成日带绿点。点某天看当日训练：按周模板（周一至周日，训练日/休息日、部位、动作清单）或当天实际记录，逐组填次数与重量并打勾；记录体重并画趋势 sparkline；动作库按部位维护 |
| **饮食计划** | 整月日历：格子显示早/午/晚排的菜与当日千卡（有加餐时多一行）。点某天开抽屉排餐（四个餐次、从菜品库勾选、看热量小计），「照这个吃」一键生成打卡；底部可标「在家吃/外卖」、点杯子记喝水（0–8 杯）；菜品库可增删 |
| **游戏娱乐** | 手填娱乐时长（按天、按类型）与本周累计柱状图；游戏清单（想玩/在玩/通关/弃坑、进度、评分）；追剧追番（看到第几集/共几集、进度条、状态）；内置 2048 与记忆翻牌，最高分自动保存 |
| **数据与设置** | 各集合条数总览与文件体积；导出 JSON / 导入 JSON（先校验并预演「将覆盖 N 条」）；备份列表与一键恢复；偏好（浅色/深色、称呼、每周起始日、自媒体平台、默认时薪）；危险区清空（需输入「清空」） |

### 跨模块能力

- **加入今天 + 回写**：开发的任务与 Bug、咨询的跟进、自媒体的内容都能「加入今天」。前三类勾掉会改源实体状态，自媒体内容只作提醒、不改发布阶段。同一来源同一天只允许一条，重复点会提示「已在今天」。（训练的回写规则在数据层已实现，界面暂未提供入口。）
- **全局搜索**：`⌘K` / `Ctrl+K` 打开命令面板，可跳模块、搜今日未完成条目、任务、自媒体内容、客户、游戏与追剧。
- **手动保存**：改动默认 300ms 自动落盘；右上角常驻「保存」按钮与 `⌘S` 可立即保存并取消待发的自动保存。
- **深浅主题**：整套设计令牌双份取值，切换即时生效并记入数据文件。
- **空状态引导**：空模块都有说明文案和下一步按钮；今日计划、自媒体、咨询可一键「填入示例」，健身动作库与饮食菜品库可「填入常用动作 / 几个家常菜」，第一次打开不是一片空白。

## 三、安装方法

### 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10/11（提供 `start.bat`）；macOS / Linux 用 `npm start` 启动，行为一致 |
| Node.js | **20.19+ 或 22.12+**（Vite 8 的要求；实际验证环境为 v22.22.2） |
| npm | 随 Node 附带，验证环境为 10.9.7 |
| 浏览器 | 桌面版 Chrome / Edge / Firefox，窗口宽度 1024 起 |

不需要数据库、不需要 Docker、不需要任何账号或密钥。

### 步骤

```bash
# 1. 进入项目目录
cd APP

# 2. 安装依赖（只有 vue、vue-router 两个运行时依赖）
npm install

# 3. 构建前端（会先跑 vue-tsc 类型检查）
npm run build
```

构建成功后目录里会出现 `dist/`，这一步只需要做一次（改了源码要重新 build）。

### 验证安装

```bash
npm run test      # 19 个测试文件、282 条用例，应全部通过
npm run typecheck # 类型检查，应无输出
```

## 四、使用方法

### 启动

**Windows**：双击项目根目录的 `start.bat`。

**任意平台**：

```bash
npm start
```

- 服务地址 `http://127.0.0.1:4173`，启动后自动打开浏览器。
- 只监听 `127.0.0.1`，局域网内其他设备访问不到。
- 重复启动不会开第二个实例：检测到端口占用时直接打开已有地址并退出。
- `start.bat` 在缺少 `dist/` 时会提示先执行 `npm install` 与 `npm run build`。
- 想换端口：`set PORT=5000` 后再启动（macOS/Linux 用 `PORT=5000 npm start`）。
- 停止：关掉那个命令行窗口，或在该窗口按 `Ctrl+C`。

### 日常开发

```bash
npm run dev
```

同时起本地服务（4173，负责 `/api`）与 Vite 热更新（5173）。写界面走 `http://127.0.0.1:5173`，`/api` 已被代理到 4173。

### 数据存在哪

| 文件 | 说明 |
|---|---|
| `data/app-data.json` | 全部数据，一个 JSON 文件 |
| `data/app-data.json.bak` | 上一次保存前的副本 |
| `data/backups/app-YYYYMMDD.json` | 每天第一笔编辑前的自动备份，最多留 14 份 |
| `data/app-data.pre-import-*.json` | 每次导入前自动存档 |
| `data/app-data.pre-reset-*.json` | 每次清空前自动存档 |
| `data/app-data.corrupt-*.json` | 数据损坏后以空白重建时，坏文件被挪到这里 |

想整体搬走，直接拷 `data` 目录即可。

### 备份与恢复

- **导出**：数据与设置 → 导出 JSON，下载 `工作生活台-YYYY-MM-DD.json`。
- **导入**：数据与设置 → 导入，先校验结构并显示「将覆盖 N 条」，确认前会自动备份当前数据。
- **自动备份**：每天第一次编辑时留一份，设置页可一键恢复，恢复前也会先保存当前状态。
- **清空**：必须输入「清空」两个字；清空前自动存档。
- **数据坏了**：如果 `app-data.json` 被改坏，程序进入只读保护，不会覆盖原文件，页面上会列出备份供恢复，也可以选择以空白数据重建。

### 保存机制

改动默认自动保存：每次编辑后 300ms 落盘，右上角显示「保存中… / 已保存 时:分 / 未保存改动 / 保存失败」。

想立刻落盘可以点右上角的 **保存** 按钮或按 `⌘S` / `Ctrl+S`：它会取消等待中的防抖，只发一次请求。还有未保存改动时关页面或刷新，浏览器会先弹确认。

写入不是直接覆盖：先备份 → 写 `.tmp` → 回读解析自检 → 存 `.bak` → 重命名替换。中途断电最多丢最后一次改动，不会留下半个坏文件。

### 快捷键

| 按键 | 作用 |
|---|---|
| `⌘S` / `Ctrl+S` | 立即保存（不等自动保存的 300ms 防抖） |
| `⌘K` / `Ctrl+K` | 命令面板：跳模块、搜条目、新建备忘 |
| `⌘J` / `Ctrl+J` | 快速备忘 |
| `Esc` | 关闭抽屉或小游戏 |

## 五、输入输出示例

下面五个例子都是真实行为，不是示意。

### 示例 1：在今日计划加一条

**输入**：在「下午」下方的输入框敲 `写 README 输入输出示例`，回车。

**输出**：`data/app-data.json` 的 `plans` 数组里多一条（id 由程序生成）：

```json
{
  "id": "plan_m3k9x2a1b7c",
  "date": "2026-11-13",
  "section": "pm",
  "title": "写 README 输入输出示例",
  "module": "plan",
  "priority": 0,
  "estimateMin": null,
  "done": false,
  "doneAt": null,
  "sourceType": null,
  "sourceId": null,
  "sortIndex": 0
}
```

页面上立刻出现在「下午」段末尾，输入框清空。标题为空时不会插入；同一标题可以重复添加（只有「加入今天」带来的来源条目才按来源去重）。

### 示例 2：「加入今天」并把源任务带成完成

**输入**：开发工作 → 某项目 → 任务列表里点某条任务右侧的「加入今天」；随后回到今日计划勾掉这条。

**输出**：新建一条带来源引用的计划项，勾选后源任务状态被改写。

```json
{
  "title": "修复上传超时",
  "module": "dev",
  "section": "pm",
  "sourceType": "task",
  "sourceId": "task_9f2c1d7e4a",
  "done": true,
  "doneAt": "2026-11-13T09:12:04.511Z"
}
```

回写规则：

| sourceType | 勾选后 | 取消勾选后 |
|---|---|---|
| `task` | `tasks[].status = "done"` | `"todo"` |
| `bug` | `bugs[].status = "fixed"` | `"open"` |
| `followup` | `followups[].status = "done"` | `"open"` |
| `workout` | `workouts[].completed = true` | `false`（数据层支持，界面暂无入口） |
| `content` | 不改阶段（只作提醒） | 不改阶段 |

反过来删掉源任务时，这条计划项保留，标题位置显示「来源已删除」。

### 示例 3：自媒体回填数据，长出趋势曲线

**输入**：自媒体 → 在任意视图点开一条内容 → 在「发布后回填」里填播放 `12000`、点赞 `860`、涨粉 `45` → 点「保存数据」。

**输出**：`media[].stats` 更新，同时追加一个按日期的历史点（同一天再填会覆盖当天那个点，不会堆叠）：

```json
{
  "stats": {
    "views": 12000,
    "likes": 860,
    "follows": 45,
    "recordedAt": "2026-11-13T09:20:00.000Z",
    "history": [
      { "date": "2026-11-11", "views": 8200, "likes": 610, "follows": 33 },
      { "date": "2026-11-13", "views": 12000, "likes": 860, "follows": 45 }
    ]
  }
}
```

切到「数据」视图，播放与点赞两条曲线按这些点绘制，右侧是「单条表现」与「平台对比」条形图。没有历史点的老数据会退回用 `recordedAt` 当唯一点，图表仍能画。

### 示例 4：导入一份备份文件

**输入**：数据与设置 → 导入 → 选一个 JSON 文件。

**输出**：先校验，再显示预演，确认后才写入。

```
文件：工作生活台-2026-11-01.json
将覆盖 128 条
plans 12 · memos 5 · media 9 · projects 3 · tasks 24 · bugs 6 · timeLogs 18 …
[确认导入]  [取消]
```

- 不是合法 JSON → 提示「不是合法的 JSON 文件」，原数据不动。
- 结构不对（缺 `schemaVersion`、某集合不是数组）→ 逐条列出问题，原数据不动。
- 确认导入前自动把当前数据存到 `data/app-data.pre-import-*.json`。

### 示例 5：直接调本地 API

服务启动后，所有数据操作都走这几个端点（`Content-Type: application/json`）。

**读全部数据**

```bash
curl http://127.0.0.1:4173/api/data
```

```jsonc
{
  "ok": true,
  "doc": {
    "schemaVersion": 1,
    "settings": { "theme": "light", "weekStart": 1, "platforms": ["视频号"], "defaultHourlyRate": 0, "userName": "" },
    "runtime": { "timer": null },
    "plans": [],
    "media": []
    // …其余 22 个集合，字段定义见 src/types.ts
  },
  "savedAt": "2026-11-13T09:20:00.000Z"
}
```

**整包写入**

```bash
curl -X PUT http://127.0.0.1:4173/api/data \
  -H "Content-Type: application/json" \
  -d '{"doc":{"schemaVersion":1,"settings":{"theme":"dark","weekStart":1,"platforms":[],"defaultHourlyRate":0,"userName":""},"runtime":{"timer":null},"plans":[],"memos":[],"media":[],"projects":[],"tasks":[],"bugs":[],"timeLogs":[],"devLogs":[],"clients":[],"engagements":[],"sessions":[],"followups":[],"weekPlans":[],"exercises":[],"workouts":[],"bodyMetrics":[],"dishes":[],"mealPlans":[],"mealLogs":[],"waterLogs":[],"games":[],"shows":[],"leisureLogs":[],"miniScores":[]}}'
```

```json
{ "ok": true, "savedAt": "2026-11-13T09:21:33.402Z" }
```

**其余端点**

| 方法与路径 | 用途 | 返回 |
|---|---|---|
| `GET /api/health` | 存活检查 | `{ "ok": true, "version": "1.0.0" }` |
| `GET /api/export` | 下载完整快照 | `工作生活台-YYYY-MM-DD.json` |
| `GET /api/backups` | 备份列表 | `{ "ok": true, "items": [{ "file", "size", "mtime" }] }` |
| `POST /api/backups/restore` | 恢复某份备份 | `{ "ok": true, "doc", "savedAt" }` |
| `POST /api/import` | 导入（同样先校验） | `{ "ok": true, "counts", "savedAt" }` |
| `POST /api/reset` | 清空，body 需 `{ "confirm": "清空" }` | `{ "ok": true, "doc" }` |
| `POST /api/rebuild` | 损坏后以空白重建，body 需 `{ "confirm": true }` | `{ "ok": true, "doc" }` |

写入失败会返回 400 并带 `code`；数据损坏处于只读保护时返回 **409**（`CORRUPT` 或 `READONLY`），前端据此切到恢复界面而不是覆盖文件。

## 六、技术构成

- **前端**：Vue 3 + TypeScript + Vite；`vue-router` 用 history 模式。无 UI 库、无图表库、无日期库——曲线、进度环、日历都是手写 SVG/CSS。
- **样式**：`src/styles.css` 一套设计令牌（表面、文字、语义色、圆角、阴影、字号），浅色/深色各一份取值，页面只引用令牌不写死颜色。
- **后端**：Node 内置 `http`/`fs`，只监听 `127.0.0.1`，负责静态文件、读写 JSON、备份与恢复。没有 Web 框架、没有数据库驱动。
- **存储**：单文件 JSON，整包防抖保存（300ms），写入走「先备份 → 写临时文件 → 回读校验 → 重命名替换」。

### 目录

```
server/     本地服务：http 骨架、JSON 存储、API
shared/     前端与服务端共用的 schema（集合名、默认设置、校验）
src/
  views/        九个页面
  features/     各模块业务逻辑与局部组件（plan/media/dev/consult/fitness/diet/play/memo/settings）
  components/   通用件：侧栏、页头、抽屉、月历、分段控件、空状态、命令面板
  store/        全局状态（db 数据与保存、ui 主题与抽屉）
  lib/          日期、ID、标签、API 封装
tests/      vitest 用例（19 个文件）
data/       运行时生成的数据与备份
```

### 测试

```bash

npm run typecheck   # 类型检查
npm run build       # 类型检查 + 生产构建
```

覆盖存储层（原子写入、备份、损坏保护、导入导出往返、重启后数据仍在）、计划回写规则、九个模块的业务逻辑、各页面交互、命令面板与快捷键、保存状态机。当前 19 个测试文件、282 条用例。

## 七、边界

- 单人单机使用，不做多用户、协作、分享、账号体系。
- 只面向桌面浏览器，窗口宽度 1024 起；更窄会横向滚动，不做手机适配。
- 不联网、不抓取平台数据：自媒体播放量等指标靠手动回填。
- 数据只有一份（外加自动备份），没有跨设备同步；换机器请拷 `data` 目录或走导出/导入。
